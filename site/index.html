Apache Airflow software factory

Issue in. Verified PR out.

GitHub says what to change. Airflow owns the lifecycle. A coding agent works in an isolated cell. Deterministic gates decide what can ship.

The algorithm

  1. 1. Take a work order. A GitHub issue selects a versioned blueprint and target.
  2. 2. Create one durable Cell. The Cell owns issue, target, epoch, state, and evidence.
  3. 3. Let Airflow schedule it. Airflow is the only lifecycle scheduler: retries, waits, approvals, and cancellation.
  4. 4. Run edits in disposable compute. The agent gets a bounded job and sandbox. It does not get release authority.
  5. 5. Check the result. Tests, review, policy, hashes, and evidence are machine-checkable gates.
  6. 6. Publish one result. The trusted control plane creates the PR. Humans keep final merge authority.

issue -> cell -> airflow -> sandbox -> evidence -> pull request

What stays non-liquid

  • Scheduling: Apache Airflow only.
  • Identity: one durable Factory Cell per issue and target.
  • Mutations: (cell_id, epoch, operation_key) is fenced or idempotent.
  • Authority: sandboxes can edit; they cannot approve, publish, or promote themselves.
  • Evidence: success, refusal, repair, latency, and cost stay attached to the run.

Sandbox support

A sandbox is disposable compute, not a scheduler. Policy support is backend-specific. The factory owns the issue-to-PR route; providers supply the execution boundary.

Each status below is the support value of that profile's row in the capability inventory, which is the single public truth for a claimed feature. A profile with no claim is an integration seam.

Toolset boundary. Configure toolset_backend = "package.module:Class" and run with --sandbox toolset. If a required isolation policy is unsupported, the run stops with StageError. The factory does not fake provider capabilities.

Blueprints are routes, not schedulers

A blueprint defines steps, limits, approvals, and sandbox choice. It compiles into work that Airflow schedules. Astronomer Blueprint users can expose the same route as software_factory without creating a second lifecycle authority.
