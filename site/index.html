How the factory runs

From work order
to pull request.

GitHub holds the work order. A blueprint sets the route. Airflow schedules each step. Tests, review, and people check the result.

GitHub credentials never
cross the line.

Model-written code executes in an untrusted sandbox. The orchestrator alone authenticates to and publishes on GitHub, and delivery crosses the boundary as a validated patch stream.

Airflow-native sandboxing

One contract. Move the cell.

The common-ai provider’s SandboxBackend becomes ToolsetSandbox. Select it with --sandbox toolset and toolset_backend, or load any compatible package.module:Class. The run stops when a required isolation policy is unavailable.

The factory owns the issue-to-PR route. The selected backend creates, executes, reconnects, and destroys the isolated work cell.

A TOML blueprint declares stages, human gates, limits, targets, sandbox profile, and PR labels. Airflow turns each file into a DAG at parse time.

[blueprint]
name = "factory"

[[targets]]
repo = "zozo123/ariflow-swfactory"
dir = "demo/target"
base_branch = "main"

[stages]
order = [
  "intent", "spec", "plan",
  "build_and_test", "review", "deliver",

[[gates]]

artifact = "intent.md"

[[gates]]

max_parallel_jobs = 4

[sandbox]
kind = "islo"

[deliver]
labels = ["factory", "agent-authored"]

The operator's client

One command
drives the line.

swf is a single native executable. Connect an environment, submit work, answer a gate, and re-derive what was delivered, from a terminal or from a script. Connecting to a factory needs no Python, no uv and no virtualenv on the operator's machine.

Install it:

install | sh 
$ curl -fsSL https://zozo123.github.io/ariflow-swfactory/install.sh | sh

It verifies the release checksum before it installs anything, needs no sudo, and installs nothing at all if the digest does not match. Prefer to read it first? The script is here, and the manual steps are the same thing by hand.

Nothing else to install

One executable per platform.

Each release carries a macOS and a Linux tarball holding the binary, LICENSE, README and generated shell completions, with a SHA256SUMS file over every asset. From a checkout, cargo build --release produces the same binary.

Scriptable

Every command answers --json.

Exactly one document on stdout, every diagnostic on stderr, and a stable exit code: 1 operational, 2 usage, 3 not found, 4 authentication, 5 unreachable, 6 conflict. The config file records the name of the variable a credential lives in, never the value.
