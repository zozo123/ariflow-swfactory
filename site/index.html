03Boundary

Security is topology.

Credentials never
cross the line.

Model-written code executes in an untrusted sandbox. The orchestrator alone can talk to GitHub, and delivery crosses the boundary as a validated patch stream.

Airflow owns authority.

  • Holds GH_TOKEN and the islo key
  • Records gates, budgets and metrics
  • Validates and applies the patch
  • Pushes the bot-owned branch

Airflow-native sandboxing

One adapter. Every backend the ecosystem ships.

The common-ai provider’s SandboxBackend becomes ToolsetSandbox. Select it with --sandbox toolset and toolset_backend; a pending provider raises a named StageError, never an import crash.

sbx resolves from released apache-airflow-providers-common-ai 0.8.0. The integration was also proven ahead of merge on Airflow 3.4.0, task-sdk 1.4.0, providers-standard 1.18.0 and common-ai 0.7.0, where islo resolved to IsloSandboxBackend.

04Blueprint

The factory is a file.

Change the line.
Not the engine.

A TOML blueprint declares stages, human gates, limits, targets, sandbox profile, and PR labels. Airflow turns each file into a DAG at parse time.

01
One file → one DAG

No per-pipeline Python.

02
Issues × targets → jobs

Dynamic task mapping does the fan-out.

03
Every job owns its state

Sandbox, approvals, branch and artifact chain.

default6 stages · 2 gates↗ hotfix5 stages · no spec↗
blueprints/default.toml 
[blueprint]
name = "factory"

[[targets]]
repo = "zozo123/ariflow-swfactory"
dir = "demo/target"
base_branch = "main"

[stages]
order = [
  "intent", "spec", "plan",
  "build_and_test", "review", "deliver",
]

[[gates]]
after = "intent"
artifact = "intent.md"
timeout_h = 24

[[gates]]
after = "plan"
artifact = "plan.md"
timeout_h = 24

[limits]
max_build_iterations = 3
budget_usd = 8.0
max_parallel_jobs = 4

[sandbox]
kind = "islo"

[deliver]
labels = ["factory", "agent-authored"]
One mapped task group per job fan_out → job[ setup → intent → approve_intent → spec → plan → approve_plan → build_and_test → review → deliver → metrics ; teardown ]
